# LE 开局事件交互草图

本资产只回答 [玩家如何启用 LE 事件并理解其整局规则与结算贡献？](https://github.com/titanxxh/open-agricola/issues/1496)。这是独立原型分支，不能直接合入产品。

## 查看

在本 worktree 中使用项目统一入口启动：`./restart-local.sh`。如果默认端口已有其他任务，使用专属端口和 `OWNED_PROCESSES_FILE`，或按 `scripts/test-environment.ts` 创建隔离环境后加载其 `test.env` 再执行同一入口。

打开启动输出的前端地址，并加上：

```text
/?prototype=le&page=lobby&variant=A&scene=create
```

保持现有 App、语言包、AuthProvider 与 PageRouter 的加载流程，在既有大厅／对局路由替换渲染内容。预览在开发环境中可直接查看，不要求登录；身份、版图、费用、结算回复都是固定演示数据。页面不会发送游戏命令，不读写真实房间。它不验证随机流、权限投影、规则计算、持久化或恢复。

## 方案

| 参数 | 差别 | 取舍 |
| --- | --- | --- |
| `variant=A` | 建局下拉框；对局顶部事件入口，点击查看完整规则 | 占地少，局内完整规则需要主动展开 |
| `variant=B` | 建局模式卡；桌面常驻规则侧栏，手机改成可折叠卡 | 易读到整局规则，手机首屏占用较多 |
| `variant=C` | 建局配置确认单；局内规则页签，按当前结算附说明 | 当前影响突出，完整规则与记录需要切换页签 |

底部浮动条或左右方向键切换方案，URL 保留方案和场景。输入框、下拉框中不截获方向键。顶部深色条属于原型控制，不是正式界面。

## 场景

`scene` 可选 `create`、`waiting`、`draft`、`solo`、`parents`、`work`、`animals`、`feeding`、`improvement`、`occupation`、`replay`。也可通过顶部场景下拉框切换。

- 建局默认关闭；可随机或指定四卡之一。等待房只显示公开配置，随机结果在模拟开局后首次显示。
- 轮抽、单人选牌与父母牌选择首帧均带事件说明。对局中可切换未启用状态。
- 动物展示事件完整方案与 Animal Tamer 完整方案，以及不可确认的混合示例。事件三宠实际位于 B1，计一个有动物的格；Animal Tamer 分放两格。
- 供养包括家庭修正后 3 → 2、1 → 0、原本 0 → 0 三例。第三例不记虚构节省，均保留完成供养步骤。
- 发展展示 Lumber Mill 与事件共同折扣，以及免费打出但保留独立支付且不返木。
- 职业展示免学费但保留 Lover 的额外 4 食物。
- 确认后的记录展示实付和来源；回放使用预先记录的结算值，不现场计算。事件与单卡贡献分开。

草图中的中文事件名用于比较界面，正式文案仍需按项目 i18n 流程处理。

## 待用户决定

建议采用 A 的常驻入口，加当前支付／供养／动物交互中的直接说明与来源明细；开局第一帧先展示事件摘要。手机完整规则使用底部弹层。B 与 C 用于比较信息密度和操作成本。
