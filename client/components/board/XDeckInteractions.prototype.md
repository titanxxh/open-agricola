# X-Deck 交互草图

本资产只回答[玩家如何操作 X-Deck 的跨玩家放置、收养、农场落位与重建？](https://github.com/titanxxh/open-agricola/issues/1554)。它在独立的原型分支上，不合入 main，也不作为正式 UI。

## 查看

规划期间曾在 owner 本机 Tailscale IP 的 8554 端口临时托管，该预览服务已于 2026-11-01 地图完成时停止。现在请直接双击同目录的 HTML 文件，不需要启动应用。

页面只用固定演示数据和固定回应：不发游戏命令，不连房间，也不验证规则计算、撤销边界或恢复。

## 前提

- **呈现基线**：[X-Deck 呈现决策](https://github.com/titanxxh/open-agricola/issues/1553#issuecomment-6559599616)。
- **人员交互**：沿用 [Legendairy Forest 交互决策](https://github.com/titanxxh/open-agricola/issues/1542#issuecomment-6541564970)已定的成员栏和带人员 id 的放人命令。
- **权威模型**：见牌堆、人员、物品与行动格、农场四张模型票。

## 内容

左边是模拟界面，右边是“接入现有能力”：复用、小改、新增、仅显示。用顶部“场景”切换；“视角”切玩家1 / 玩家2；“方案”只在有分歧的场景出现。

- `overview` 总表：X-Deck 的全部交互点，逐项写显示与输入、接入方式，并链接到场景。
- `x16` 指定放置：抽牌者在行动板上为对方点格，再交回对方选人放下。
- `x18` 收养：**甲** 分步（choice → 恰好 5 个货物 → 对方安置动物）/ **乙** 合并面板。
- `x17` 放糖果：**甲** 先选分数再点恰好 2N 个格 / **乙** 点格时自动算分。
- `x08` 回家前：X08 选空格并不放人用格，X09 拿 1 个货物。
- `merchant` 商人购买：after 窗口里的可选项，加统一支付。
- `x03` 变形器：选方式，换自己的货物或换累积格。
- `x15` 回家末进贡：逐人选择付货物或归还成员，含保底灰掉。
- `x22` 冻结与解冻：回家时选人；目标轮开头可先放他。
- `x23` 麦田怪圈落位：选相邻两格并预览拆除后果，之后整理动物。
- `x21` 烧房与重建：逐人整理宠物；翻修格出现重建替换；选相邻空格并支付。
- `x12` 毛球供养：喂养结算里多一行。

本机已用 Playwright 把每个场景 × 每一步 × 双视角 × 两种方案 × 桌面 / 手机外框全部过了一遍，并点了每个可操作元素，共 188 个状态，没有页面错误。

## 用户决定

用户于 2026-11-01 看过草图后，五项都按推荐确认，详见 [resolution](https://github.com/titanxxh/open-agricola/issues/1554#issuecomment-6559900056)：

- 不新增请求类型；共用五处小改：行动格目标、恰好 N 个货物、拆除预览、毛球供养一行、来源说明条。
- X18 收养选甲（分步），X17 放糖果选甲（先选分数）。
- 跨玩家交接、保底灰掉和其余场景都按草图。

乙方案留在本分支供追溯。正式实现按已确认的权威模型重写，不直接提升本草图。
