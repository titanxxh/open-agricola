# Workshop generation acceptance

Workshop generation changes need ordinary automated coverage for the affected behavior and a local model tool round trip. The model check uses the local Codex session with the ChatGPT subscription and explicitly selects Terra; it does not call the DeepSeek API. A successful round trip is evidence for that run and request, not proof that every generated card is correct.

The Workshop capability contract remains fail-closed. Capability names require the two-player Session behavior coverage described in [ADR 0025](../adr/0025-workshop-capability-contract-is-fail-closed-and-opened-by-tests.md). Timing and payment are covered directly by [`workshop-timing-payment-session.test.ts`](../../server/__tests__/workshop-timing-payment-session.test.ts). The browser UT authored by the model runs in the isolated Worker and is separate from those tests; adoption still requires matching source validation and browser UT results. See [`workshop-generation.spec.ts`](../../e2e-tests/workshop-generation.spec.ts) and [`workshop-browser-card-tests.spec.ts`](../../e2e-tests/workshop-browser-card-tests.spec.ts) for browser coverage.

Keep local acceptance artifacts under ignored `output/tmp/`. Do not commit model credentials, private protocol messages, or temporary generated artifacts. Record the request, selected model, tool calls and observable results needed to assess the run without claiming broader model quality from a single example.

Before a model run, use `codex login status` and app-server `account/read` to confirm ChatGPT subscription authentication. Select the exact available `gpt-6.1-terra` model from `model/list`; do not substitute another model or fall back to an API key. See the official [authentication](https://learn.chatgpt.com/docs/auth) and [app-server](https://learn.chatgpt.com/docs/app-server) documentation.

Use a temporary local app-server bridge to the production browser `GenerationAttempt` and its four tools. Keep the bridge, rerun command, source snapshot identity, every written source/test revision, and results in the ignored acceptance batch. This is owner-local verification, not a supported external-agent product entry or a permanent provider adapter. For unmerged work, references may use actual files from the frozen local Git commit with the usual blob-hash verification; record that scope separately from GitHub connectivity.

Check generated source independently through two-player `GameSession` behavior assertions based on the request. Keep these assertions separate from the model's own browser UT, and do not feed their failures back into generation or discard failed runs. Existing composed behavior regressions live in [`workshop-composed-behaviors-session.test.ts`](../../server/__tests__/workshop-composed-behaviors-session.test.ts).
